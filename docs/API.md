# API

All routes except `GET /health` and `GET /ui` need the header `X-API-Key: <API_KEY from .env>`.
(`/ui` is a static page; it asks for the key and sends it with each call. In demo mode the key
can be any value.) Interactive docs: `/docs` (Swagger UI, generated by FastAPI).

Several callers: set `API_KEYS=acme:<key>,beta:<key>` (keys at least 16 characters). Each caller has
its own usage limits.

**Usage limits.** `POST /ask` and `POST /retrieve` cost money, so they are limited per caller:
`ASK_PER_MINUTE` (default 20) and `ASK_PER_DAY` (default 500); `0` means no limit. Over a limit the
answer is `429` with a `Retry-After` header (seconds). Successful responses carry
`X-RateLimit-Remaining-Minute` and `X-RateLimit-Remaining-Day`. In demo mode the limit is per
client IP (`DEMO_PER_MINUTE`, default 30). Every response has an `X-Request-ID` header, the same id
as in the server log line for that request.

`collection_id` is optional everywhere and defaults to `default`. A question only sees documents in
its own collection.

## `GET /health`

```json
{ "status": "ok", "mode": "live" }
```

`mode` is `live` or `demo`.

## `POST /documents`

Add or update one text document. Idempotent by content hash.

Request:

```json
{
  "collection_id": "harbor-goods",
  "doc_id": "returns-policy",
  "title": "Returns Policy",
  "version": "2026-01",
  "text": "Customers may return unused items within 30 days of delivery. ..."
}
```

Response `200`:

```json
{ "collection_id": "harbor-goods", "doc_id": "returns-policy", "status": "created", "chunks": 6 }
```

`status` is `created`, `updated` (hash changed, chunks replaced) or `unchanged`.
Errors: `401` bad key, `422` bad `doc_id`/`collection_id` or empty text, `503` embedding service down.

## `POST /documents/pdf`

Add or update one PDF (multipart form: `file`, plus `collection_id`, `doc_id`, `title`, `version`).
Text is extracted per page; each chunk keeps its page number.

Response `200`:

```json
{ "collection_id": "harbor-goods", "doc_id": "supplier-terms-alpine", "status": "created",
  "pages": 3, "chunks": 9 }
```

Errors: `401` bad key, `422` not a PDF, too large, too many pages, or no extractable text (scanned
PDFs are not supported), `503` embedding service down.

## `GET /documents`

Query: `collection_id` (optional).

```json
{ "documents": [ { "collection_id": "harbor-goods", "doc_id": "returns-policy",
                   "title": "Returns Policy", "version": "2026-01", "source_type": "text",
                   "pages": null, "chunks": 6 } ] }
```

## `POST /ask`

Request:

```json
{ "question": "How many days do customers have to return unused items?",
  "collection_id": "harbor-goods",
  "mode": "hybrid" }
```

`mode` is optional: `vector`, `hybrid` (default) or `hybrid_rerank`. It exists so the same question
can be run in every retrieval mode for measurement. `k` is not a parameter; the server decides.

Response `200`, answered (`chunk_text` is the retrieved chunk, so a UI can highlight
`chunk_text[quote_start:quote_end]`; `run_mode` is `live` or `demo`):

```json
{
  "status": "answered",
  "answer": "Customers have 30 days from delivery to return unused items.",
  "citations": [
    { "doc_id": "returns-policy", "title": "Returns Policy", "chunk_id": "harbor-goods:returns-policy:2",
      "page": null,
      "quote": "Customers may return unused items within 30 days of delivery.",
      "quote_start": 118, "quote_end": 180,
      "chunk_text": "..." }
  ],
  "retried": false,
  "mode": "hybrid",
  "latency_ms": 0
}
```

`page` is filled by the server from the stored chunk (null for text documents). `quote_start` and
`quote_end` are character positions inside the chunk text, so a UI can highlight the quote.
(Numbers above are illustrative of the shape, not measured values.)

Response `200`, refused (the documents do not contain the answer):

```json
{ "status": "abstained", "answer": "Not in the documents.", "citations": [], "retried": false,
  "mode": "hybrid" }
```

Response `200`, could not prove itself after one retry:

```json
{
  "status": "needs_human",
  "answer": null,
  "citations": [],
  "retried": true,
  "errors": [ "quote not found in chunk harbor-goods:returns-policy:2" ],
  "mode": "hybrid"
}
```

When `mode=hybrid_rerank` and the reranker failed, the response also carries `"rerank": "skipped"`.

Errors: `401` bad key, `429` usage limit reached, `409` no documents ingested in that collection, `422` question empty or over
500 characters, or unknown `mode`, `503` Claude or Voyage unreachable.

## `GET /ui`

One static HTML page (no framework, no build step): a key field, a question box, the answer, a status
badge (`answered`, `abstained`, `needs_human`), and each citation with the quote highlighted inside
its source text, the document title and the page. A visible "demo mode" badge when `mode` is `demo`.

## Schema Claude must answer with (pydantic, `app/schemas.py`)

```
Answer:   answer: str            # the answer text, or "Not in the documents."
          abstained: bool        # true only if the documents do not contain the answer
          citations: list[Citation]
Citation: doc_id: str
          chunk_id: str
          quote: str             # an exact sentence or phrase copied from that chunk
```

The model is not asked for `page`, `title` or positions. The server adds them after the check.

Rule in code, not in the prompt: `abstained=false` with zero valid citations is a failure.

## `POST /retrieve`

The chunks retrieval returns for a question, without calling Claude (free with local embeddings).
Same request as `/ask`. Useful to debug retrieval and to compare modes.

```json
{ "mode": "hybrid", "rerank": null,
  "chunks": [ { "chunk_id": "harbor-goods:returns-policy:1", "doc_id": "returns-policy",
                "title": "Returns Policy", "page": null, "score": 0.032, "text": "..." } ] }
```

## `GET /demo/questions`

In demo mode, the recorded questions (and the metadata of the run they came from). In live mode
it returns an empty list.

## Demo mode differences

- No key is needed; `POST /documents` and `POST /documents/pdf` return `409` (read-only).
- `/ask` and `/retrieve` return `404` "demo mode: this question is not recorded" for a question that
  is not in `data/recorded/answers.json`. Recorded answers still pass through the evidence check.

## Live mode without `ANTHROPIC_API_KEY`

`/ask` returns `503` "ANTHROPIC_API_KEY is not set". Ingest and `/retrieve` still work.
